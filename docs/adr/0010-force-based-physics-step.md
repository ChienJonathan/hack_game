# All movement is Forces integrated by one physics step, with Collisions that exchange motion

Movement no longer lives in each process. Player walking, guard and behavior-tree pursuit and `mv` only apply Forces to a body (`mass × acceleration` for walking, pursuit and a Throw, so mass only matters in Collisions). One `PhysicsWorld.step` then adds up the Forces, applies `drag` and ground `friction` (not while the body is in a Throw) and `max_velocity` (which only limits what a Force can add, never speed that a Collision gave), moves every body, resolves Collisions and calls an `onCollision` hook. A tick runs the processes (which apply Forces), then the physics step, then `ContactResolver` (triggers only, ADR 0008), then the defeat check. This replaces the order of ADR 0009, where flight ran before the processes.

A Collision exchanges motion along the line between the two box centres: `v1' = (m1·v1 + m2·v2 + m2·e·(v2 − v1)) / (m1 + m2)` with `e = e1 × e2` (each object's Restitution), only while the bodies are approaching. A body that was at rest takes part with its real mass only if the speed it would gain is at least `min_collide_move_velocity` (50 px/s); below that it counts as infinitely heavy and the mover bounces off with `−e × v`. A body with no Force applied this tick and a speed below `min_velocity` (5 px/s) is set to rest; the "no Force" condition keeps heavy bodies from being zeroed every tick before they can start moving. Bodies already overlapping at the start of a tick (a Weapon leaving the holder's hand) are pushed out along the shallowest axis; only the body that moved this tick is displaced. The room bounds clamp the body and zero the speed along the normal, with no bounce.

Which pairs Collide is decided by the Collider Tags alone (`collidesPhysically`): Character–Character, Character–Obstacle, Obstacle–Obstacle and Weapon–Obstacle. A Weapon passes through Characters and other Weapons, which keeps the Impact Damage trigger working. The boulder now carries an `obstacle` tag. Weapons get a collisionbox (its size comes from the scaled dagger size or `colliderWidth`/`colliderHeight` in `room1.ts`; the Level Editor does not edit it yet); a held Weapon, and a defeated Character, take no part in the physics.

`MvDrive` replaces `ThrownFlight`. It only applies `mv_acceleration`, tracks a moving target, and snaps and stops a Throw that comes within `max(step, ARRIVAL_RADIUS)`. Any Collision (not a trigger) ends the Throw: the speed is kept, no more Force is applied, and the physics step carries on. A Throw that would Collide never reaches its target, which is intended. Hitting the target object itself still marks it discovered. Impact Damage applies only while the Weapon is in a Throw. A Thrown Character keeps its own walking or pursuit Force, so Forces simply add up and the player can pull against `mv`.

Every drive (walking, pursuit, braking) only works up to its own top speed: a body knocked faster than `maxSpeed` is not braked, turned around or pushed further by it, and only drag and friction slow it until it is below that speed again. `friction` is a share of the speed per second like `drag` (default 5), so a hard knock fades quickly at first.

`drag`, `mass`, `max_velocity`, `friction` and the new `restitution` are physics properties, not `mv` ones. They move out of `mv_attr` to the top level of the object, each an optional override of a global default in `physicsConstants.ts`; `mvConstants.ts` keeps only `mv_acceleration`. `mv_attr` is removed with no compatibility, and the save schema version is raised so old saves read as absent. Room bounds move from two hard-coded copies to `Room.bounds`.

Alternatives were Phaser Arcade or Matter (a second source of truth for position outside the domain state, a frame-driven step instead of the fixed 60 Hz tick, no headless runs for tests and editors, and the rules above would have to override its collision response anyway), putting the response in `ContactResolver` (loses the contact normal and its triggers do not move bodies), and a separate knock velocity layered over the existing movement code (two velocity systems, and the processes would keep fighting the pushed body's speed). Walking bodies are heavy movers, so a guard that closes in on the player now takes part in Collisions; this changes how it feels to fight and may need tuning of `restitution` and the guard's acceleration.
